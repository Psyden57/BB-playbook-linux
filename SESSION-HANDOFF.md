## 0x2819 record format — SOLVED (from deckard `blacklist.py`, supplied by user)
- `NV_OSSTORE_NotSupportedOS_NUM = 0x2819` (OS blocklist), `NV_OSSTORE_NotSupportedRADIO_NUM = 0x2852` (RADIO blocklist; irrelevant — units have no 4G radio).
- Payload = up to 10 entries of `OSRangeAndType(rangeStart, rangeEnd, osTypeBitMask)`, `struct '=III'` = 12 bytes each LE, max 120 bytes (`SUPPORTED_OS_LIST_SIZE = 10`). Reading empty data = "missing" (no blocks). First `EMPTY (0,0,0)` entry truncates the list.
- `STP_PROTOCOL_TYPE__SHIPPING_OS = 4` → mask `1<<4 = 0x10`.
- Gate semantics: candidate OS version is blocked if it falls within any entry's `[rangeStart, rangeEnd]` for a matching type mask.
- Working unit's record: `rangeStart=0`, `rangeEnd=0x02080501` (= `user2os([2,1,0,1281])` — the 2.1.0.1917 OS sets floor 2.1.0.1281), `mask=0x10`. Exact `user2os` encoding of `0x02080501` still unknown (internals live in deckard `metrics`).
- **Clearing the blocklist = writing an EMPTY (0,0,0) entry or zero bytes to 0x2819.** On the bricked unit this must go through the ramloader USB path (QNX can't boot) — need the ramloader's NVRAM-write opcode from `FUN_80103b90` (~line 5036).

### get_security_mode SOLVED (dcmd 0x4008050e → `is_secure_cpu`, FUN_00022e9c)
- Reads the **bootrom metrics blob (0xE8 = 232 bytes)**; security field read as u32 near offset **0x78** (empirically: `+0x78 = 0` on this HS unit → secure; `+0x7C = 0xB4`; Ghidra frame-offset ambiguity ±4). Returns `1 - field`; 0 = HS, 1 = GP.
- Devctl handler outputs ONE u32: `1 - is_secure_cpu()` → **output[0] = 0 ⇒ SECURE (HS) CPU**. Tool's second value (3) is uninitialized stack garbage.
- HS confirmed 3×: CONTROL_STATUS `0xAE8` (DEVTYPE=2=HS), driver is_secure_cpu, NVRAM signature enforcement active ("Secure device: verifying NVRAM signature").
- Bootrom metrics live on the eMMC boot region: 16-byte header at `bootbase+0x30` with cookie **0xd7b02d1f**, then blob = `{version u32 (hi.lo), size u32, payload...}`. Blob starts ASCII `"RIM BlackBerry Device"` + build host `ec_agent` + `Mar 24 2011 15:31:02` (bootchain build timestamp).
- `FUN_00022fa4` selects NVRAM signature key by HW type (DAT_0003f608): types 3/4/8 → **"NVRAM Sig-development"**; others → r036/r057/r061/r072/r042 keys.
- OS metrics: driver reads 0x1CC bytes from the IFS on `/dev/hd1|hd2` at offset **0x10002c**; magic `0xC3D0E193` @+0x9c, **OS type @+0xD4** (os_type 6 → treated as insecure/dev).

`0x40080501` record count · `0x4008050d` bootrom metrics (returns n bytes written) · `0x4008050e` security mode · `0x4008050a/0b` manufacturing data (12 bytes each) · `0x40080510` FUN_0002532c · `0x40080511` FUN_0002474c · `0x40080512` FUN_000238dc · `0xC0080502` get record (hdr {out result, in id} + data iov; EOVERFLOW→needed size in hdr) · `0xC0080503` permissions · `0xC0080504` is_protected · `0xC0080505` exists · `0xC0080506` delete secure · `0xC0080507` delete insecure · `0xC0080508` write secure record · `0xC0080509` write record. `/dev/nvram` also supports **lseek/pwrite at offset = record id** (xtype 5) — this is how deckard's blacklist.py writes the blocklist.

### NvUpdateRecord write path (FUN_0001db70) — protection model
- Record attrs via `FUN_00019ea4(id)` → flags: **bit0 = conditional-write-protected, bit4 = RIM_ENCR (AES-encrypted, SHA256-derived key, hu_* crypto)**.
- bit0 + `_DAT_0003fb68 != 0` → **-17 (write denied)**. `_DAT_0003fb68` = value of **NVRAM record `0x2050` (NV_OSSTORE_NVR_CONDITIONAL_WRITE_NUM)**, cached at init. **If 0x2050 == 0 → protected records ARE writable from userspace.**
- 0x2819 reads back plaintext ⇒ bit4 NOT set ⇒ no encryption obstacle.

## Ramloader USB protocol — FULLY MAPPED (decompile × bb10mt source cross-ref)
Client source: `bb10mt-main/` (Pascal). Key files: `ramloader.pas` (flow), `bbloader.pas` (loader cmd client + **full opcode name table in comments**), `bbusb.pas` (wire format + bootrom cmds), `nvre.pas` (NVRAM flash format), `uflash.pas`/`mct.pas` (image parts).

### Wire format (loader channel 2, `Channel2` in bbusb.pas)
```
TX/RX packet: u16 size(=len+8) | u16 cmd | data[len] | u32 crc32(bytes[0..len+4])
Send on USB channel/interface 2; response echoes cmd as resp id; then read one extra frame.
```
Bootrom mode commands ($F0xx): PING $F000, READ_METRICS $F001, EXIT $F002, WRITE_RAM $F004, EXECUTE_RAM $F005, PASSWORD $F006 (challenge/salt/iterations), DEVICE_NUKE $F008. Modes: USB product id 1 = bootrom, $8001 = loader, SetMode switches.

### Loader opcode table (name from bbloader.pas; verified vs decompile dispatchers FUN_801032ac / FUN_80103b90 / FUN_8011ae30)
```

21 bootrom log              B1 flash IDs                    EF80 reboot (resp 80C7)

AF write DWORD to 8023977c  B3 loader action log (NVRAM rec 0x2033 append)   F9 40 SIGNATURE_TRAILER (resp 4006)
B0 bugdisp log (paged, end D0)   B4 flash regions info (resp D2)   C0 40 COMPLETE (resp 4006)
B5 flash info               B7 HASH_BOOTROM                 C4 READVERIFY (addr,size,val → decompile: erase+write loop, resp 28)
```

Loader NVRAM primitives: read `FUN_8010b954(id,buf,len)` / status `FUN_8010b7b8(id)` / write `FUN_8010b990(id,buf,len)`. ### NVRAM on-flash format (nvre.pas — raw eMMC layout)
```
Block header (28B): u16 unk1 | u16 BlockNum | u32 Revision | u32 DataCrc(crc32 data) | u32 unk2 |
                    u32 BlockLen | u32 DataLen | u32 HdrCrc(crc32 header-4)   + data + u32 'NVRE' (0x4552564E)
```

### Main USB dispatch loop (decompile ~line 19560) — routing map
`0xda/0xaf/0xb3/0xae/0xc4/0xc3/0xde/0xe0/0xe8/0xe9` → FUN_80103b90 · `0xe4/0xe5/0xe6` → FUN_80102dc4 (CREAD) · `0xf7/0xf8` → FUN_8011fdd8 (write staging) · `0xf9` → FUN_801205cc (signature trailer) · `0xfd/0xee/0xc0/0xdc/0xf3` → FUN_8011ae30 · rest → FUN_801032ac · unknown → resp 0x15 "unknown cmd".
- **`0xDD FLASH_DUMP NOT IMPLEMENTED` in loader_06001A06** (routes to FUN_801032ac which ignores it) — bb10mt's comment table covers the whole BB10 family; the PlayBook build lacks some.
- **CREAD (`0xE4` init / `0xE5` read) = the flash-dump channel** (FUN_80102dc4): E5 takes `dword addr @payload[0:4], dword size @payload[4:8]` (≤0x3FE8, sector-aligned), reads eMMC sectors (FUN_80119e0c), responds `0xE9` with data encrypted under the session stream (FUN_80104984). **E4: the session keys are LOADER-SIDE PRNG-GENERATED** (FUN_80105318 = RNG bit-stream read, NOT a USB read — see "CREAD — REINTERPRETED" below); the host only sends `{u32 totalRead}` in the $E4 packet. **E5 dumps are not decryptable without RIM's private key** (session key leaves only via $EB RSA).
- **`0xF7` write** (FUN_8011fdd8): streams ≤0x10000 chunks into a staging buffer, flushes in 0x20000 units; destination driven by the image-placement state machine (PreFlash/metadata), NOT arbitrary-address. `0xFD`+`0xC0` (FUN_8011ae30): stage-into-DAT_8011b38c (≤0x80000) + commit (FUN_8011ad78 = erase @DAT_8011ae00 + write staged); FUN_801206c8 on C0 does signature-verify + NVRAM record write.
